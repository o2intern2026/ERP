# contracts/services.md — public Application Service signatures (law)

Cross-module **synchronous** reads and writes go only through these interfaces (ERP_PLAN §0.2 rule 3); state changes still travel through events (`events.md`). The PHP interfaces in the frozen zone `app/Support/Contracts/` are the authoritative signatures; this file gives the semantics. Real implementations live in the owner module's `Services/` and are bound in that module's ServiceProvider at the checkpoint shown; until then `App\Support\Fakes\*` (bound by `FakeServicesProvider` when `USE_FAKE_SERVICES=true`) implements the same interface.

## Conventions
- ids are `int`; money is integer cents (`App\Support\Money` at the edges); dimensions mm; weights kg; timestamps ISO-8601 strings with offset. Phase 1 uses typed arrays (shapes in PHPDoc) rather than DTO classes.
- Business outcomes are **returned, never thrown**: shortfall, missing rate, POA, blocked groups. Throw only for programmer errors (unknown id → `ModelNotFoundException`, bad enum → `InvalidArgumentException`).
- Every method that writes runs inside its own `DB::transaction()` and publishes its events through `OutboxPublisher` in that transaction.
- Changing a signature is a contract change (`CHANGE_REQUESTS.md`). Seat C may add optional trailing parameters or additive array keys at a checkpoint; nothing is removed or renamed inside a phase.

## 1. `StockService` (Warehouse, C) — ERP_PLAN §4.3 rules 1, 2, 4, 10; §8.2
```php
onHand(int $clientId, int $asnLineId): array{qty_on_hand:int, qty_reserved:int, qty_available:int}
reserve(int $clientId, int $orderId, array $lines): array   // lines: list<{order_line_id, asn_line_id, qty}>
release(int $orderId, ?int $orderLineId = null, string $reason = 'order_cancelled'): int
```
- Quantities are cartons; a pallet unit counts the cartons it holds. Only `putaway`-completed, `condition = good` stock is on hand; `qty_available = qty_on_hand − qty_reserved`.
- `reserve` row-locks the candidate `stock_units` (FIFO by `received_at`), writes `stock_reservations`, and returns per line `{order_line_id, asn_line_id, requested_qty, reserved_qty, shortfall_qty, reservation_ids}`. Partial reservation is normal, not an error. The `order.confirmed` consumer that calls it emits `stock.reserved` when every line is fully reserved, otherwise `stock.reservation_failed` (with the shortfalls) — the consumer holds the correlation context.
- `release` marks active reservations `released`, writes `stock_ledger` (`movement_type = release`) and returns cartons released; the `order.cancelled` / `order.reduced` consumers emit `stock.released`.

## 2. `OrderService` (Orders, X1) — §3.7.2 A4, §4.6 B2c
```php
createFromAsn(int $asnId, string $groupingKey = 'mark_address_fba'): array{orders: list<{order_id, order_no, asn_line_ids}>, blocked: list<{consignment_mark, reason, asn_line_ids}>}
awaitingAsn(int $clientId): list<{order_id:int, order_no:string, job_id:int, job_no:string, consignment_mark:?string, deliver_to_name:?string, deliver_to_suburb:?string, deliver_to_state:?string, requested_date:?string, operational_status:string, unlinked_lines:int, total_lines:int, unlinked_cartons:int, collection_requested:bool}>   // CR #119: the client's from_stock orders in received / confirmed with ≥ 1 goods line whose asn_line_id is null, oldest first — the ASN page's 从订单导入货物行 candidates. CR #125 (additive): `collection_requested` = the order came from a portal 入库清单 carrying 需要我们上门提货 (`order_imports.errors.context.inbound.collection`) — the ASN page warns so attaching it to an existing ASN never silently drops the client's request
attachOrdersToAsn(int $asnId, array $orderIds, ?int $actorId, ?string $containerNo = null): array{orders:int, lines:int, merged:list<string>, cancelled:list<string>, job_no:string}   // CR #119: merges the orders into the ASN's Job (refuses another client's order / a Job that already carries an ASN / a Job with undelivered outbox_events — `orders.inbound.errors.events_pending`), adds one goods line per unlinked order line via InboundService::addOrderLinesToAsn (passing `containerNo` through as each line's `container_no`), links both ways, backorders confirmed orders quietly; merged = order numbers moved, cancelled = emptied Job numbers
```
- Groups the ASN's received lines by consignment_mark + deliver_to (name, address, state, postcode) + fba_reference; one `from_stock` order per group, `source = manual` (creator is the coordinator), joined to the ASN's Job; order lines point at `asn_line_id` and quantities use received (not expected) cartons.
- Lines already generated (`asn_lines.order_line_id` set) are skipped. A group whose lines disagree on address or FBA reference is not created and is returned in `blocked`.
- Same code path as manual / Excel / portal / API creation; the only public entry point for creating orders from other modules.

## 3. `TransportOptionService` (Transport, X2) — §5.3, §5.6 B5c/B5d
```php
quote(int $shipmentId, string $stage, ?DateTimeInterface $triggeredAt = null): list<{transport_quote_id, carrier_id, source, service_level, cost_cents, customer_price_cents, eta_days, is_recommended, is_cheapest, is_fastest, quoted_at, expires_at}>
estimate(int $clientId, array $request): list<{carrier_id, carrier_name, source, service_level, customer_price_cents, eta_days, is_recommended, is_cheapest, is_fastest}>   // CHANGE_REQUESTS #118: the same adapters, pricing and flags for a request with no shipment behind it (portal 获取估价); nothing written, no exception
```
- `stage = preliminary` prices declared packages at order confirmation; `stage = final` prices measured packages after `outbound.packed` (pure-transport orders: declared packages are final).
- `$triggeredAt` (optional, CHANGE_REQUESTS #120): the moment of the event that requested the quotes — the `order.confirmed` payload `confirmed_at` (fallback: envelope `occurred_at`) for a `pickup_deliver` order. An automatic final confirmation (client choice within `variance_tolerance_percent`) is dated this moment via `QuoteSelectionService::select(..., ?DateTimeInterface $confirmedAt = null)`, so `shipment.quote_confirmed.confirmed_at` / `is_urgent` follow the client's decision time, not outbox / cron / retry time. A person's confirmation (portal, shipment page) leaves it null = now().
- `CarrierAdapter` is the frozen interface `App\Support\Contracts\CarrierAdapter` (added with B5e, see `carriers.md`): `source()`, `capabilities()`, `quote()`, `book()`, `cancel()`, `label()`, `tracking()`. Phase 1 sources: `manual`, `own_fleet`, `transdirect`; `eiz` is No-Go.
- Asks every active `CarrierAdapter` (`own_fleet`, `transdirect`, `eiz`, `manual`), writes `transport_quotes` rows (`quote_stage`, `status = quoted`) and returns them. Customer price: own_fleet = fixed rate item; third party = `cost × (1 + markup)` where markup comes from the client's rate item (carrier × service level override) else `clients.default_markup_percent`.
- Flags (§5.6 B5d): cheapest = lowest customer price; fastest = lowest eta; recommended = cheapest among options meeting the requested date, with the `own_fleet_preference_percent` tie-break. Final vs preliminary variance above `variance_tolerance_percent` (default 10) returns quotes but leaves the shipment in `quoted` awaiting re-confirmation.
- Selection and confirmation are Transport pages, not this service; confirmation emits `shipment.quote_confirmed`.
- **Intake (module service `ShipmentIntakeService`, CHANGE_REQUESTS #124):** `fromAsnCollection(array $envelope): ?Shipment` — `asn.collection_requested` → the ONE `inbound_collection` shipment of the ASN (`asn_id`, `order_id` null, sender = `collection_address`, receiver = the ASN's warehouse, items = declared packages else goods lines, zone = pickup postcode, tailgate at pickup by the client's `TR-TAILGATE` threshold), quoted at the `final` stage at once; a higher `activity_version` re-quotes the same shipment (status back to `quoting`, earlier quotes `requoted`, selection cleared), an older / equal one is a replay, a booked one refuses and logs. `cancelAsnCollection(array $envelope): ?Shipment` — `asn.collection_cancelled` → `booking_cancelled` while not booked. Client choice (CHANGE_REQUESTS #125): `TransportOptionService::clientPreference()` reads `asns.collection_preference` (query builder, read-only) for a shipment with `asn_id`, and `resolveFinalVariance` treats it exactly like `orders.transport_preference` — same option within `variance_tolerance_percent` → selected as the client (`preferenceActor`: a still-active user of the client, else system) dated the request moment; otherwise `quoted` awaiting re-confirmation; a re-request re-runs it against the latest explicit decision (private `collectionReference`: earlier final selections replayed oldest first — same option within tolerance of the current reference leaves it, anything else becomes it, in its maker's name; review 2026-09-15). Without a preference the dispatcher / customer service confirms on the shipment page. The pickup tailgate rule is ONE static helper, `App\Modules\Transport\Support\CollectionTailgate::required(int $clientId, array $packages, array $lines, ?RateService $rates = null): bool`, and the collection carrier request ONE builder, `ShipmentQuoteRequestFactory::collectionSender(array $address)` + `collectionRequest(int $clientId, array $sender, ?array $receiver, array $items, bool $tailgatePickup, ?string $readyDate, string $description): ?array` — Transport's shipment and the portal estimate (`PortalTransportEstimate::collectionOptions`) both use them, so the request is the same for the same data.
- **CHANGE_REQUESTS #118 — the client decides:** the portal order form lists `estimate()` options next to the warehouse 估价 and the client ticks one (`orders.transport_preference`, Orders). At `order.confirmed` the preliminary quote for that option is selected as the client's own choice (`selected_by = client`, the ordering user); at `outbound.packed` the final quote for the same option is confirmed automatically while its price stays within `variance_tolerance_percent` of the reference (the selected preliminary quote, else the client's choice). Otherwise the shipment stays `quoted` and the client confirms in the portal; the coordinator's "确认" is 代客确认.

## 4. `RateService` (Billing, C) — §6.3, §6.4, §6.7 A5/A6a
```php
price(int $clientId, string $chargeCode, float $qty, array $context = [], ?DateTimeInterface $at = null): array
thresholds(int $clientId, string $chargeCode): ?array
suggestPalletClass(int $clientId, int $lengthMm, int $widthMm, int $heightMm, float $weightKg): ?string
```
- `price` returns `{charge_code, rate_item_id, rate_card_id, rate_card_version, uom, qty, rate_cents, amount_cents, min_charge_applied, is_poa, missing_rate, calculation_snapshot}`. Lookup: client's active card at `$at` (default now) → the client's bound standard card → `missing_rate = true` (amount null, **never 0**). `is_poa = true` when the rate item is POA or a threshold is exceeded (`max_gross_weight_kg`, `max_line_count`). `min_billable_qty` floors the quantity and sets `min_charge_applied`; `min_charge_cents` floors the amount. `cost_plus` items need `context.cost_cents`. `percent` items need `context.base_cents` (the amount the surcharge applies to, e.g. the freight for `TR-FUEL`); without it `is_poa = true`, snapshot `reason = no_base_cents` — never $0 (CR #99).
- `context` keys: `pallet_class, weight_kg, zone, carrier_id, service_level, cost_cents, container_size, unpack_mode, line_count, gross_weight_kg, pallet_source, is_urgent, allocated, warehouse_id, storage_tier` (`charge-codes.md` says which code reads which). **`warehouse_id` (CHANGE_REQUESTS #126):** a rate item with `warehouse_id` matches only a context naming that same warehouse — a context without `warehouse_id` never matches it (the `carrier_id` pattern; review 2026-09-15), so `thresholds()` (empty context: pallet-class bands, `tier_value_threshold_cents`, tailgate, delivery thresholds), manual charges and events without a warehouse always read the all-warehouse row (`warehouse_id` NULL); a warehouse row adds +16 to the specificity, so for its own warehouse it beats the all-warehouse row (carrier 8, service level 4, zone 2, band / pallet class 1). `StorageBillingService` passes it on every weekly line (pallet storage, quarantine, the bottom-level surcharge, pallet rental, carton / CBM storage, pickface slots); other callers do not yet, so a MEL / SYD row for any other code is not used until its caller passes `warehouse_id`; `storage_tier` is informational (`bottom` on the surcharge). **Thresholds are enforced by the real service since CHANGE_REQUESTS #122** (until then only `FakeRateService` did): `line_count > threshold_json.max_line_count` or `gross_weight_kg > max_gross_weight_kg` → `is_poa = true`, snapshot `reason = max_line_count | max_gross_weight_kg`; an absent context value never trips a cap. `allocated = true` (a member's share of a shared box) prices rate × qty and skips `min_billable_qty` / `min_charge_cents`.
- `thresholds` returns the effective rate item's `threshold_json` (client card → standard card), e.g. `TR-TAILGATE → {tailgate_weight_kg: 25}` for Orders' tailgate rule and `WH-DEVAN-20-LOOSE → {max_line_count: 20}` for Warehouse.
- `suggestPalletClass` implements §4.8 from the client's storage items: standard → oversize_high → oversize_wide; `weight ≥ min_weight_kg` → `overweight`; `null` = beyond every band (POA, `needs_review`). The receiver may override with a reason.

## 5. `JobService` (Platform, C) — §1.6, §2.4 A27
```php
create(int $clientId, string $jobType, array $attributes = []): array{job_id:int, job_no:string}
summarize(int $jobId): array{job_id, job_no, client_id, job_type, operational_status, revenue_status, cost_status, estimated_revenue_cents, actual_revenue_cents, estimated_cost_cents, actual_cost_cents, margin_cents, margin_is_estimate}
cancelIfEmpty(int $jobId, string $note): bool   // CHANGE_REQUESTS #117: cancel a Job nothing refers to any more (the per-order loose Job after its order was merged into a shipment Job); false while orders / ASNs / shipments / charges / documents still point at it, or while outbox_events with this job_id are still pending / failed (their consumers would write under a cancelled Job — #119 review)
moveOrder(int $orderId, int $toJobId): int   // CHANGE_REQUESTS #119: re-home an order and the records that refer to it into another Job of the same client — the explicit list is `orders`, then `shipments`, `customer_quotes`, `exceptions`, `packages`, `outbound_dispatches`, `warehouse_tasks` (rows with that order_id), `carrier_costs` of those shipments, and `documents` with related_type = order; this is the ONE sanctioned cross-module write of job_id (db-schema.md ownership note) and lives only in Platform. Charges / invoices / ledger / events never move; returns the records moved besides the order
```
- The only way to create a Job (`jobs` is a shared platform table). `job_no` = `JOB-YYYYMMDD-NNNN`. `attributes`: `reference`, `notes`.

Cost and margin are never returned to client-role callers (server-side, M1).
- **Client-role callers** (global client scope active) receive the summary **without** `estimated_cost_cents`, `actual_cost_cents`, `margin_cents`, `margin_is_estimate` — the cost / margin rule is enforced in the service, not in views (M1).
- Job numbers are `JOB-YYYYMMDD-NNNN`, sequence per day, allocated under a row lock (M1).

## 8. `ManifestParser` (Orders, X1; used by Warehouse B2b) — §3.6, §3.7.2 A4, §4.6 B2b
```php
parse(string $path): array{rows: list<Row>, errors: list<{row, column, message}>, warnings: list<{row, column, message}>}
```
- One `Row` per goods line of the real 《需派送货物清单》: `row, consignment_mark, description_cn, description_en, hs_code, material, usage, brand, package_type, carton_qty, unit_qty, unit_price_cents, total_price_cents, actual_weight_kg, length_mm, width_mm, height_mm, cbm, deliver_to_name, deliver_to_phone, deliver_to_address, deliver_to_state, deliver_to_postcode, fba_reference`.
- Hard errors (missing mark, non-numeric quantity) exclude the row; the pre-check "same consignment_mark, different deliver_to / fba_reference" is a **warning** (B2b lets the forwarder fix the list before the container lands; A4 blocks the group at order creation). Import bookkeeping (`asn_imports` / `order_imports`) belongs to the caller, not the parser.
- **Accuracy hardening, CHANGE_REQUESTS #123 (additive — the shape above is unchanged):** every `errors` / `warnings` entry also carries `label` (the column header as it appears in the sheet, else the Chinese field name from `orders.imports.columns.*`) and its `message` reads `第 :row 行「label」…` in Chinese (row 0 + column `file` for file-level notes); rows additionally carry `deliver_to_suburb`, `external_ref`, `requested_date` (Y-m-d or null), `service_level` (enum or null) and `raw_json`. Format is sniffed from the bytes (zip → XLSX, OLE → error `xls_unsupported` naming 另存为, else text CSV — so a renamed `.xls` / `.txt` still parses). CSV encoding: UTF-8 BOM / UTF-16 LE / BE (BOM or NUL pattern) / valid UTF-8 / else GB18030, warning names the encoding; delimiter comma / semicolon / tab sniffed on the first lines. Cells: full-width → half-width (`mb_convert_kana` "as"), NBSP → space, zero-width characters removed. Headers: the alias table accepts the common Chinese / English variants, case- and punctuation-insensitive, "*" / brackets stripped; `No.` / `Qty` / `Quantity` / `数量` / `件数` count cartons only when no 箱数-type column exists (otherwise 数量 / 件数 / Qty are unit counts); the header row is the one within the first ten that maps the most columns (title rows skipped; XLSX rows keep Excel's own row number). Units: length / width / height ×10 when the header names cm; a 单件重量 / Unit weight header is multiplied by 箱数 into `actual_weight_kg` (the line total) with one file-level warning; 箱数 accepts unit words ("10箱", "3 ctns") and refuses decimals. Phones stay text: spaces / dashes / brackets removed, +61 / 61 → 0, a 9-digit number padded with a warning, scientific notation / float exports refused. Postcodes: 4 digits inside an Australia Post range, 3-digit padded (NT / ACT) with a warning, else refused; states: code / full name / lower case / dotted / Chinese → code, unknown refused, missing state derived from the postcode range with a warning, mismatch warned. Package words (纸箱 / carton / 托盘 / pallet / 快递袋 / 木箱 / 圆筒 / 平板包装 / 栈板) → `OrderEnums::PACKAGE_TYPES` code, anything else kept as typed. Identical rows are warned as 重复行 and still read. Fixtures + one test per rule: `tests/Feature/Orders/ManifestParserAccuracyTest.php`, `tests/Fixtures/imports/`.
- **Form rows, CHANGE_REQUESTS #128 (additive):** `fromRows(list<array<string, mixed>> $rows): array{rows, errors, warnings}` — rows typed on a form instead of read from a sheet (the portal 手工建立入库清单). Each posted row is keyed by the canonical field names (`consignment_mark, description_cn, description_en, package_type, carton_qty, unit_qty, actual_weight_kg, length_mm, width_mm, height_mm, deliver_to_name, deliver_to_phone, deliver_to_address, deliver_to_suburb, deliver_to_state, deliver_to_postcode, fba_reference, external_ref, requested_date, service_level, storage_tier` — `SpreadsheetManifestParser::FORM_FIELDS`; unknown keys ignored, missing keys empty), numbered 1..n by position (a blank row is skipped but keeps its number, as on a sheet), and goes through EXACTLY the normalisation and validation `parse()` applies to a sheet row — cleaning, carry-down of blank consignee cells under the same 唛头, the duplicate-row warning, phone / postcode / state / package words / date / 存储等级 rules, the consistency warning per mark — with the same Chinese `第 N 行「列名」…` messages, the column named by `orders.imports.columns.*` (`label` on every entry). Dimensions are mm (no cm header), the weight is the line total (no 单件重量 column), an empty `storage_tier` is `standard` without being a declaration. Same return shape as `parse()` (+ `raw_rows` keyed by the Chinese column labels). The Fake returns the rows untouched (numbered) with no errors.
- **存储等级, CHANGE_REQUESTS #126 (additive):** rows carry `storage_tier` — null when the sheet has no 存储等级 / 存储要求 / 库位等级 / storage tier column, `standard` for an empty cell, 底层 / 最底层 / bottom / 地面 → `bottom`, 标准 / standard → `standard`, anything else → row error `invalid_storage_tier` naming the column — and `storage_tier_declared` (true only for a recognised non-empty cell). The declared-value pre-fill (`tier_value_threshold_cents`) belongs to the caller (`OrderImportService`), which also sets `storage_tier_source` (`client` for portal, `staff` for staff imports, `value_rule` for the pre-fill); `AsnImportService` maps a declared cell with source `staff`.

## Fakes: rules of use
- `USE_FAKE_SERVICES=true` in `phpunit.xml` and CI; a seat turns it on locally while its dependency block is unmerged. The flag must be `false` in production.
- Fakes hold state in memory per process; they are singletons for a request / test. Never write a test that depends on a Fake behaving like the database.
- When the real implementation lands, its Feature tests must pass the same contract assertions as `tests/Feature/Platform/FakeServicesTest.php`.

## 9. Billing services (C, `block/c4-billing`)
- `App\Modules\Billing\Services\ChargeEngine` (A6a): `applyEvent(array $envelope): list<Charge>` — runs the active `charge_rules` for the event, prices through `RateService`, writes `charges` with rate + calculation snapshots under the idempotency key `(source_activity_id, charge_code, activity_version)`. Missing rate → `missing_rate` exception, no charge; POA → `needs_review`; a higher `activity_version` reverses the older charges (uninvoiced: original + audit twin marked `reversed`; invoiced: billable negative twin). `manual(...)` (reason required), `review(Charge, amountCents, note)`, `reverse(Charge, reason)`.
